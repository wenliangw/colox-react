# 记忆同步纪律（corrections）

## 讨论 ≠ 决策：只记用户拍板与明确表态

为什么：会话里的调研/方案讨论被误落盘成 taste，用户纠正「我们在讨论，而不是在决策」——记忆必须只承载真实决策，讨论过程是噪声。

- 落盘前问三连：**这是事实？是我的推荐？还是用户拍板？** 只有第三类（或带明确表态的偏好：「我喜欢 / 我不喜欢 / 永远不要」）才写 taste / 决策节点 / architecture 变更。
- 用户说「了解一下」「明白问题了」「暂时不考虑」「都看看」——都是讨论态，不落盘，直到用户拍板或明确表态。
- 「用户好奇了解某技术」≠「用户偏好该技术」；被纠正过的具体案例：css-in-js 调研（2025）。
- 清理时同样按此标准：删讨论性条目，保留决策及其直接后果（如路线 A 定案 + 四个打包 taste）。
