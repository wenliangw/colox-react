# 注释卫生：JSDoc 多行与换行

代码注释格式的防漏清单（Textarea 交付期被用户指出「很多注释格式没有换行」——13 处单行挤写 + 5 处 `*/` 附尾的混合式）。

## 写/改 JSDoc 注释后自查格式

- **改这里**：新增或移动任何 JSDoc/类型字段注释（`/** ... */`），或把注释从实现文件挪进 `types/`。
- **必须检查**：
  - [ ] **不写单行挤写**：再短的注释也 `/**` 起、`*` 续行（`/** Minimum height... */` 不行——短不是免检理由）。
  - [ ] **闭合 `*/` 独立成行**：不用 `/** text\n * more. */` 这种闭合符贴文末的混合式。
  - [ ] 一行一个 `*` 续行符号，属性 tag（`@default` 等）单独成行。
  - [ ] 收工时跑一遍审计：`grep -rn '/\*\* [^*]*\*/' src/<component> --include='*.ts' --include='*.tsx'`（结果应为空——注意合法多行注释的闭合行会匹配 ` \*/$`，别把误报当违规）。
  - [ ] 移动注释时同步检查目标文件里已有的旧格式（本次 types/ 迁移把三种格式混进了一个文件）。
- **为什么**：品味规范「JSDoc 多行书写」明文要求多行，但执行中被「注释短一行够」偷懒绕过；用户目视代码直接发现，说明这是会被人盯的硬指标，不是软偏好。
