# 注释卫生：JSDoc 闭合符与换行

代码注释格式的防漏清单。（前科：Textarea 交付期被指出多处 `*/` 附尾；2026-10 用户再次澄清规则并抓到 input-number/date-picker/input 五文件 12 处附尾式。）

## 写/改 JSDoc 注释后自查格式

- **改这里**：新增或移动任何 JSDoc / 类型字段注释（`/** ... */`），或把注释从实现文件挪进 `types/`。
- **必须检查**：
  - [ ] **能一行放下就写单行**：判据 = `缩进 + /** 文本 */` ≤ printWidth（100）。短内容单行合法，**不要机械摊开**——前科：一轮批量把 35+ 处单行摊成多行，随后又收敛回单行；用户两次指正「有些内容确实比较少，可以单行注释」「一些单行能放下的注释也调整为单行注释吧」。
  - [ ] **放不下（>100）/ 含 tag / 多段 / 列表 → 三段式多行**：`/**` 独占首行、`*` 逐行续写、` */` 独占末行；**禁止附尾式**——内容写了多行却把 `*/` 留在最后一行文本尾部（`/** text\n * more. */`）。tag（`@default` 等）单独成行，续行 `*` 后单空格。
  - [ ] **收工跑两个审计**：① 附尾式（应 0）：`grep -rnE '^\s*\*[^*]*\*/\s*$' src/<component> --include='*.ts' --include='*.tsx'`；② 新增单行注释是否 ≤100：`git diff -U0 src | grep -E '^\+' | grep -E '^\+\s*/\*\*' | awk '{print length($0)}' | sort -rn | head`。（早期版本把单行注释本身当违规目标，方向反了。）
  - [ ] 移动注释时同步检查目标文件里已有的旧格式（types/ 迁移期曾把三种格式混进一个文件）。
- **为什么**：用户目视代码指出附尾式「很不美观」——这是会被盯的硬指标。前科根因：早期一次批量「转多行」的脚本只换了行、没把闭合符独立出来（`*  text. */` 的双空格痕迹即那次遗留），且顺手把大量本可单行的注释也摊开了。
