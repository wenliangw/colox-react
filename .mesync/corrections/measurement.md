# layout 测量预算：折叠/切片计数

## 改这里

任何「按可用宽度折叠/切片」的测量逻辑（chips 行折叠、标签行截断、响应式菜单收纳），以及 ResizeObserver 驱动的布局重算。

## 必须检查

- **测量表面不能是会随内容回缩的容器自身**：若预算 = 被折叠容器的自身宽度，而该宽度又随切片内容缩短（flex 收缩 + 贪婪 sibling 吸收空余），下一次测量就拿到更窄的预算 → 计数自我坍塌（前科一：Select +M 首版把行自身宽当预算，折叠 → 行更窄 → 更折 → 归零只剩徽标，且观察的是行、行宽不再变 → 永不重测）。
- **预算 = 参考容器宽（如 `colox-select__inner`）− 恒定占位之和，任何元素的「当前宽度」一概不进预算**：control 的 `min-width` 底线（读 computed `minWidth`，不读 `offsetWidth`）、trailing 固定宽、flex gap。**「当前宽 > 底线时按当前宽受让」这类分支是陷阱**——贪婪元素（`flex:1`、basis 0）在切片折叠后会把空余全部吸收，当前宽永远大于底线，分支恒真 → 预算又坍回切片内容宽 → 同一条螺旋（前科二：修复一版加了 controlWidth 分支想覆盖「输入增长挤压」假想场景，但 flex:1/0% 基底的 control 根本挤不动行——假想场景不存在，分支只带来归零；用户现象=改完后一个 option 都不展示只剩 +M）。
- **resize 观察对象 = 预算的真实因素**：观察参考容器（说明书：以 inner 为容器参考值）。被折叠容器/贪婪 sibling 的尺寸变化不是预算因素，观察它们反而制造反馈回路。
- **测量函数保持无状态**：读 refs/DOM 当前值，不闭包渲染次数——避免 observer 回调闭包陈旧值；gap 类主题常量缓存于 ref，联动 value 变化（非只长度）。
- **复杂测量抽 hooks/utils**：折叠计数（纯函数 utils：countFittingTags）+ 预算/回测/observer 生命周期（hook：useTagFold）分离，渲染单元只消费结果——不要在 children 单元里堆 Dom 测量代码。
- **回归测试必须覆盖陷阱分支**：模拟指标时给贪婪 sibling 一个远大于底线的「当前宽」（前科二正是 mock 成与底线相等的 8px 而盲区漏测；升级后 mock 220，旧分支必挂）。
- **jsdom/SSR 无布局守卫**：宽度 ≤ 0 时回退全量、徽标隐藏，绝不把 0 当预算。
- 为什么：同一个组件吃同一类螺旋两次（行宽 → control 当前宽），两次都是「预算里混进了会随切片反馈的量」；恒定占位 + inner 参考 + 无状态测量一次到位。
