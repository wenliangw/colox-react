# layout 测量预算：折叠/切片计数

## 改这里

任何「按可用宽度折叠/切片」的测量逻辑（chips 行折叠、标签行截断、响应式菜单收纳），以及 ResizeObserver 驱动的布局重算。

## 必须检查

- **测量表面不能是会随内容回缩的容器自身**：若预算 = 行自身宽度，而该行宽度又随切片内容缩短（flex 收缩 + 贪婪 sibling 吸收空余），下一次测量就拿到更窄的预算 → 计数自我坍塌（Select 多选 +M 前科：折叠 → 行更窄 → 更折 → 归零只剩徽标，且一旦坍塌不再重测——观察的是行，行宽不再变）。
- **预算取「不依赖切片结果」的稳定量**：父容器宽 − 各 sibling 的最小占位（control 的 `min-width` 底线、trailing 固定宽、flex gap）。用 sibling 的**底线值**而不是当前值——当前值会被贪婪增长污染（空闲被 flex:1 吃掉时当前宽冗余开支）。
- **resize 观察对象 = 预算的真实因素**：观察父容器（容器响应）+ 贪婪 sibling（输入串增长挤压时行宽会变）+ 行自身（让位重测），缺一个方向就有盲区。
- **测量函数保持无状态**：读 refs/DOM 当前值，不闭包渲染次数——避免 observer 回调闭包陈旧值；gap 类主题常量缓存于 ref，联动 value 变化（非只长度）。
- **jsdom/SSR 无布局守卫**：宽度 ≤ 0 时回退全量、徽标隐藏，绝不把 0 当预算。
- 为什么：Select 多选折叠首版把「行自身宽」当预算，用户现象=继续选中后空间明明够却只剩 +M、全选后零 chip；修后 budget = inner − control 底线 − trailing − 2×gap，观察 inner/control/row 三方。带模拟指标的回归测试兜底（断言行宽与放宽双向）。
