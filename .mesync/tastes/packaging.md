# 打包与构建取向

来源：树摇优化实践 + 用户对自写装配插件的质疑（「通用构建需求应该有官方做法/现成插件」）+ 路线 A 定案。

- **官方原生优先**：打包能力尽量用 Vite/Rollup 原生配置（`lib.entry` 多入口、`cssCodeSplit` 都是原生）；要补时顺序 = 官方插件（vite-plugin-dts 已在用）→ 社区成熟插件 → 自写小段构建代码（仅当原生与现成都表达不了，如「分包 + 全量两全」）。
- **数据定夺**：打包/摇树决策用消费端实测说话（只引 Button 产物 2.7KB vs 全量 10.6KB、残留清零），不靠理论推断。
- **一行样式优先**：`style.css` 单文件全量是默认体验；CSS 分包等组件样式膨胀到值得维护装配逻辑（或引入 lib-inject-css 接线）再说。
- **入口即树摇**：一个组件一个构建 entry + exports 子路径——模块级树摇确定性最高，消费端无需关心 rollup 内部 chunk。
- **样式路线锚点（业界调研 2025）**：2018–2022 一代（antd v5/MUI/Chakra v1-2）涌向运行时 CSS-in-JS 换「引组件即引样式 + 动态主题计算」，2023+ 零运行时回流（Chakra v3 → Panda、antd → CSS 变量模式、MUI Pigment）——SSR/流式/运行时税把钟摆拉回「构建期 css + 运行时变量换肤」，恰与 Colox 现有架构同侧；将来组件膨胀优先增强变量/变体制（CVA 变体 = 动态性前置到设计系统层），不引入运行时 cssinjs。
