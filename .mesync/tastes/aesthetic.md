# Colox 审美基准（草稿 v1 — 与你共同沉淀）

这是**跨项目**的审美基准（不只 docs 站）：以后做任何产品界面，先过这份清单再动手。
横向研究对象：ant.design / mui.com / chakra-ui.com / ui.shadcn.com / radix-ui.com（2026-09 截图实测）。

## 一、横向观察：主流官网的共性（不是风格，是纪律）

1. **hero 永远展示真实产品界面**：MUI/Chakra/Radix = 左文 + 右侧真实 UI 卡堆叠（日历、任务卡、团队列表、代码块）；shadcn/antd = 居中标题 + 下方真实组件网格。**没有一家把 hero 留成空白**——空白必须被渐变、面板或代码填满。
2. **一个自信的主色**：MUI 蓝、Chakra 青、Radix 紫、antd 蓝，只用在标题高亮、主按钮、链接、pill 上；其余全是黑白灰。
3. **hero 标题两色处理**：MUI 首行蓝 + 其余黑；Chakra 把「with speed」染青并加底色；Radix 用衬线 + 紫色 pill。标题本身就是设计事件。
4. **标题上方永远有一个 announcement pill**（版本/新组件/博客入口）——「项目活着」的信号。
5. **字体层级靠极端反差**：hero 48-64px + 紧字距 vs 正文 14-16px 灰；不靠颜色堆层次。
6. **氛围 = 一层柔和的颜色**：Radix 粉紫渐变网格、Chakra 青色 blob、antd 蓝紫渐变、MUI 白+蓝、shadcn 纯白（靠排版与卡片网格补偿）。**有渐变的不一定花，纯白的必须有极强排版**。
7. **卡片三件套**：白底 + 1px 发丝边 + 12-16px 圆角 + 一层柔和的影子（不是硬阴影）；浮起卡片可以轻微叠压制造纵深。
8. **按钮永远成对**：一个实心主行动 + 一个 ghost/tinted 次行动，层级一眼可辨。
9. **组件陈列 = 真实组件 + 边框卡 + 名称标签**（五家全一致）。
10. **留白慷慨，但从不空**：每块空白都有渐变、面板或代码兜底。

## 二、Colox 的翻译（我们的资产与约束）

- **资产**：六族语义色（brand/gray/info/error/warning/success）+ 三轴命名系统 + 全 token 化的样式层。
- **签名选择**：多数库只有**一个**主色；我们的独特性 = **六族色谱系统**。所以「六族」要成为页面的视觉签名（受控剂量地成串出现），而不是全灰下去。
- **性格**：工程严谨（mono 标签、token、三轴词汇）——审美上偏「精密仪器」而非「消费级玩具」。

## 三、落到具体手法（token 级）

| 层面     | 手法                                                                                                                                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 氛围     | hero 区一层柔和渐变 wash（`brand-subtle` → transparent 之类），分区之间用 bg-default / bg-subtle 交替形成「章节」                                                                                                                 |
| 主色     | 主行动与关键高亮用 `--colox-color-brand-solid`；六族只做展示性、成串出现                                                                                                                                                          |
| 标题     | hero 48px 级、字距 -0.02em、两色处理（默认色 + 一处 brand 或 muted 强调）；section 标题 24px                                                                                                                                      |
| 正文     | 14-15px、`text-muted`、行高 1.6                                                                                                                                                                                                   |
| 卡片     | `border-muted` 发丝边 + `radius-lg` + `shadow-sm/md` 柔和影；hover 时换边色（可加 `shadow-md`）                                                                                                                                   |
| 浮起场景 | 真实控件组合成「标本面板」，用 `shadow-lg` 轻微叠压，制造纵深                                                                                                                                                                     |
| 按钮     | 实心（brand solid）+ ghost/outline 成对出现                                                                                                                                                                                       |
| 技术细节 | mono 字体承担所有「工程感」信息（版本、token 名、命令行、属性名）                                                                                                                                                                 |
| 动效     | 滚动显现（一次性 fade+rise，见 src/components/reveal）、hero 一次性入场、卡片 hover 轻抬（-3px + shadow-md）、状态变化微动画（playground 代码行 pulse、终端逐行进、详情面板淡入）——一律走 motion token，reduced-motion 门自动收敛 |
| 图文     | **每个卖点配一个 figure**：流程/管线用 mono 节点 + 箭头、场景用 CSS 画的迷你示意图（表格骨架/多主题面板/对话气泡）、概念用 token 上色的方块；纯文案段落 = 未完成                                                                  |
| 章节节奏 | 区块编号（01 — start、02 — design language…）+ 交替 surface（白 / bg-subtle 带）+ 每章一句 sub；禁止一长条白底到底                                                                                                                |

## 四、动手前的检查清单

1. 这块空白有内容吗？（渐变/面板/代码/真实 UI 四选一）
2. 主色只用在了该用的地方吗？（主行动 + 关键高亮，别泛滥）
3. 标题是不是足够大、足够紧、足够有对比？
4. 卡片是不是「发丝边 + 圆角 + 柔和影」三件套？
5. 有没有展示**真实产品界面**（而不是抽象占位）？
6. 工程感细节（mono/命令/token 名）出现了吗？

## 五、已拍板的分叉（2026-09 与用户共同确认）

- **主色策略 = 六族色谱当签名**：主行动仍用 brand，但六族作为页面的色彩签名成串出现（hero 标本调色板、页脚色谱条、六族色卡区）。理由：多数库只有一个主色，六族是我们独有的资产。
- **hero 构图 = 左文 + 右侧「设计语言标本」浮动面板**：左边 pill + 双色大标题 + 标语 + 双按钮 + 安装命令 chip；右边一张带柔和影子的真实控件标本面板（palette/variant/tone/size 四行）。hero 永不留白。
- **氛围强度 = 柔和渐变 wash 打底**：hero 与关键分区各铺一层低饱和家族渐变（brand-subtle / blue-subtle），分区之间 bg 交替形成章节。
- **字体个性 = 无衬线 + 极端字重/字号反差**：hero 45.5px / 字距 -0.02em / 双色处理，正文 14-15px 灰；不引入衬线（中文衬线风险）。

### 落地的实现手法（可复用）

- **家族 tone 三件套走 CSS 变量**：一个类携带 `--f-solid / --f-muted / --f-subtle`（如 `.familyBrand`），卡片底色、色板方块、色谱条共用同一份变量——新增家族只加一个类。
- **浮起面板用 shadow-lg**，平面卡片只用发丝边：影子的有无 = 「这个东西浮在场景里还是页面上的元素」。
- **渐变要克制但要可见**：2-3 层低饱和 radial-gradient 叠在 bg-subtle 上；暗色下同一份 token 自动变成深色辉光。
