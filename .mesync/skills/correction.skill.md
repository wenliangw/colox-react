# mesync 纠错维护心法

本文件讲「怎么识别和维护纠错」。结构与字段规范见 `.mesync/rules/correction.rule.md`。

## 识别

- 用户指出错误、或故障被定位后，问一句：**将来做同类操作，会不会再漏？**会 → 纠错。

## 落盘

- 主干写「改这里 → 必须检查哪里」，清单式、语言简洁；一行「为什么」做锚。
- 按行为分类落入 `.mesync/corrections/<分类>.md`：已有类并入更新，新类建新文件（防单文件膨胀）。

## 触发时机

- 出错定位后**顺手**落/更新一条，不打断主线任务。
- 动手前：若任务属改名、契约变更、多包联动等高危操作，先 `read .mesync/corrections/` 对应分类对照检查，再动手。

## 诚实纪律

- 对用户声明的「已验证 / 已入库 / 已修复」必须是真实执行过的结论；被追问「写到哪里了」时，先承认未落盘再补齐，不狡辩。
