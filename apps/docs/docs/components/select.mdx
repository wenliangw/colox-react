# Select

A searchable single/multiple select built on the shared form-family shell: the
trigger rows sit flush with same-tier `Input`/`Checkbox`/`Radio` controls, and
the popup is a portal listbox modeled as an ARIA 1.2 editable combobox — focus
stays in the trigger organ, arrows walk options, Enter picks.

Selection is `options`-driven (label data, server-ready), `onChange` carries
`{ event, value, option }`.

## Options

A select takes `options: SelectOption[]` — `value` is the selection truth, `label` the display. Disabled members are skipped by the keyboard walk and mouse clicks:

<Select
  defaultValue="fig"
  options={[
    { value: 'apple', label: 'Apple' },
    { value: 'fig', label: 'Fig' },
    { value: 'cherry', label: 'Cherry (out of season)', disabled: true },
  ]}
/>

```tsx
const options: SelectOption[] = [
  { value: 'apple', label: 'Apple' },
  { value: 'fig', label: 'Fig' },
  { value: 'cherry', label: 'Cherry (out of season)', disabled: true },
];

<Select options={options} value={selected} onChange={({ value }) => setSelected(value)} />;
```

`onChange` fires with `{ event, value, option }`: `event` is the triggering
click/press, `value` the next selection (`''` = none in single mode), `option`
the chosen/toggled option object (undefined when cleared).

## Search

`showSearch` embeds the search organ — the same naked input organ the `Input`
shell uses. Single mode flips the organ between the selected label (closed) and
the query stream (open):

<Select
  showSearch
  options={[
    { value: 'apple', label: 'Apple' },
    { value: 'apricot', label: 'Apricot' },
    { value: 'pineapple', label: 'Pineapple' },
  ]}
  placeholder="Type to search fruit"
/>

The default matcher is a case-insensitive substring over label and value;
pass `filterOption` to replace it, and `onSearch(query)` fires on every query
change for server-side delegation. `optionRender` replaces an option's panel
row content (the trigger keeps showing the raw label).

## Multiple

`mode="multiple"` renders one removable chip per value; the panel stays open
after each pick, Backspace on an empty query removes the last chip.

<Select
  mode="multiple"
  defaultValue={['apple', 'date']}
  options={[
    { value: 'apple', label: 'Apple' },
    { value: 'banana', label: 'Banana' },
    { value: 'date', label: 'Date' },
  ]}
/>

## Popup rows (optionSize)

The panel is its own layout context: its typography does not follow the trigger
size. `optionSize` (default `'md'`) sets the row tier independently — here a `lg`
trigger with `xs` rows:

<Select
  defaultOpen
  size="lg"
  optionSize="xs"
  value="apple"
  options={[
    { value: 'apple', label: 'Apple' },
    { value: 'banana', label: 'Banana' },
  ]}
/>

## Form collection

`name` mounts hidden native inputs — one in single mode, one per value in
multiple mode — so native `FormData` collects the selection:

<Select
  name="fruit"
  defaultValue="banana"
  options={[
    { value: 'apple', label: 'Apple' },
    { value: 'banana', label: 'Banana' },
  ]}
/>

### SelectOption

| Prop     | Type        | Notes                                       |
| -------- | ----------- | ------------------------------------------- |
| value    | `string`    | The selection truth and FormData value.     |
| label    | `ReactNode` | Display; also the default search surface.   |
| disabled | `boolean`   | Skipped by keyboard walk; clicks are inert. |

### SelectChangePayload

| Prop   | Type                                                    | Notes                                                                             |
| ------ | ------------------------------------------------------- | --------------------------------------------------------------------------------- |
| event  | `MouseEvent<HTMLElement> \| KeyboardEvent<HTMLElement>` | The triggering interaction (option click/press, chip remove or the clear button). |
| value  | `string \| string[]`                                    | The next selection.                                                               |
| option | `SelectOption`                                          | The chosen/toggled option; `undefined` when cleared.                              |

### Ref

`ref` exposes the focus organ: the trigger button in plain single mode, the
embedded input in searchable/multiple modes — typed
`SelectRef = HTMLInputElement | HTMLButtonElement`.

The shell also accepts all native `div` attributes; `id` lands on the focusable
organ so `<label for>` targets the real control, and `aria-label` overrides the
organ's default reachable name (selected label or placeholder text).

V1 intentionally excludes tags-in-placeholder, optgroups, virtual scrolling,
typeahead selection and remote debounce — requests welcome.
