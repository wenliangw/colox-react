# Radio

Radios capture single selections; `Radio.Group` owns the picked value.

## States

<Radio>Unchecked</Radio> <Radio defaultChecked>Checked</Radio> <Radio invalid>Invalid</Radio>
<Radio disabled>Disabled</Radio>
<Radio readOnly defaultChecked>
  Read-only
</Radio>

`readOnly` pins the value: the control stays focusable, readable and submitted, but a
click or key press reverts and publishes nothing. It is the family's own behaviour
(native `readonly` means nothing to a radio), announced through `aria-readonly`, and it
does **not** dim the control — dimming is the disabled language.

A group-level `readOnly` freezes the current pick: members stay focusable and
announce `aria-readonly`, and no selection change is published.

`invalid` paints the unfilled state only — a selected radio keeps its brand ring
(same visual priority as [Checkbox](./checkbox)).

## Sizes

<Radio size="xs">extra small</Radio> <Radio size="sm">small</Radio> <Radio size="md">medium</Radio>
<Radio size="lg">large</Radio>

## Group

Members declare a `value` to join the group's single selection:

<Radio.Group defaultValue="apple">
  <Radio value="apple">Apple</Radio>
  <Radio value="banana">Banana</Radio>
  <Radio value="orange">Orange</Radio>
</Radio.Group>

## Props

| Prop     | Type                           | Default |
| -------- | ------------------------------ | ------- |
| size     | `'xs' \| 'sm' \| 'md' \| 'lg'` | `'md'`  |
| invalid  | `boolean`                      | `false` |
| value    | `string`                       | —       |
| onChange | `({ event, value }) => void`   | —       |

A member's `onChange` reports its own state through the family payload — `value` is a
boolean here (the next checked state), while the `value` prop stays the group key.

```tsx
<Radio checked={picked} onChange={({ value }) => setPicked(value)}>
  Solo pick
</Radio>
```

It also accepts all native `<input>` attributes (`size`, `type` and `onChange` are the
library's own).

### Radio.Group props

Members inherit `size`, `name`, `disabled`, `invalid` and `readOnly` from the group; a
member's own prop wins for `size`/`name`/`invalid`, while `disabled`/`readOnly` are
sticky (a restricted group cannot be opted out of). `onChange` fires with `{ event, value }` — `event` is the triggering member's native change event, `value` the next selection.

| Prop         | Type                                 | Default |
| ------------ | ------------------------------------ | ------- |
| value        | `string`                             | —       |
| defaultValue | `string`                             | —       |
| onChange     | `({ event, value: string }) => void` | —       |
| size         | `'xs' \| 'sm' \| 'md' \| 'lg'`       | `'md'`  |
| disabled     | `boolean`                            | `false` |
| readOnly     | `boolean`                            | `false` |
| invalid      | `boolean`                            | `false` |
| name         | `string`                             | —       |

A group-level `invalid` turns every member red and announces `aria-invalid` on the
members (own `invalid` on a member wins, so opting one out works).
