# Checkbox

Checkboxes capture boolean states and, through `Checkbox.Group`, multi-select sets.

## States

<Checkbox>Unchecked</Checkbox> <Checkbox defaultChecked>Checked</Checkbox>
<Checkbox indeterminate>Indeterminate</Checkbox> <Checkbox invalid>Invalid</Checkbox>
<Checkbox disabled>Disabled</Checkbox>
<Checkbox readOnly defaultChecked>
  Read-only
</Checkbox>

`readOnly` pins the value: the control stays focusable, readable and submitted, but a
click or key press reverts and publishes nothing. It is the family's own behaviour
(native `readonly` means nothing to a checkbox), announced through `aria-readonly`, and it
does **not** dim the control — dimming is the disabled language.

A group-level `readOnly` pins every member (sticky, like `disabled`).

`indeterminate` marks the partially-selected state visually (a bar); `checked` stays the
single source of truth for events and form values, and the bar clears on the next click.

## Sizes

<Checkbox size="xs">extra small</Checkbox> <Checkbox size="sm">small</Checkbox>
<Checkbox size="md">medium</Checkbox> <Checkbox size="lg">large</Checkbox>

## Group

Members declare a `value` to join the group's selection array:

<Checkbox.Group defaultValue={['apple']}>
  <Checkbox value="apple">Apple</Checkbox>
  <Checkbox value="banana">Banana</Checkbox>
  <Checkbox value="orange">Orange</Checkbox>
</Checkbox.Group>

## Props

| Prop          | Type                           | Default |
| ------------- | ------------------------------ | ------- |
| size          | `'xs' \| 'sm' \| 'md' \| 'lg'` | `'md'`  |
| invalid       | `boolean`                      | `false` |
| indeterminate | `boolean`                      | `false` |
| readOnly      | `boolean`                      | `false` |
| value         | `string`                       | —       |
| onChange      | `({ event, value }) => void`   | —       |

`value` is the string form token here, so a box's own `onChange` reports its state
under the payload's `value` as a boolean (`value` prop → form data, payload `value` →
the next checked state).

```tsx
<Checkbox checked={agreed} onChange={({ value }) => setAgreed(value)}>
  I agree
</Checkbox>
```

It also accepts all native `<input>` attributes (`size`, `type` and `onChange` are the
library's own).

### Checkbox.Group props

Members inherit `size`, `name`, `disabled` and `readOnly` from the group; a member's
own prop wins for `size`/`name`, while `disabled`/`readOnly` are sticky (a restricted
group cannot be opted out of). `onChange` fires with `{ event, value }` — `event` is the triggering member's native change event, `value` the next selection array.

| Prop         | Type                                   | Default |
| ------------ | -------------------------------------- | ------- |
| value        | `string[]`                             | —       |
| defaultValue | `string[]`                             | —       |
| onChange     | `({ event, value: string[] }) => void` | —       |
| size         | `'xs' \| 'sm' \| 'md' \| 'lg'`         | `'md'`  |
| disabled     | `boolean`                              | `false` |
| readOnly     | `boolean`                              | `false` |
| invalid      | `boolean`                              | `false` |
| name         | `string`                               | —       |

A group-level `invalid` turns every member red and announces `aria-invalid` on the
members themselves (the ARIA `group` role does not support the attribute); a member
that sets its own `invalid` keeps it — the opt-out works too:

```tsx
<Checkbox.Group invalid value={picked} onChange={({ value }) => setPicked(value)}>
  <Checkbox value="apple">Apple</Checkbox>
  <Checkbox value="banana" invalid={false}>
    Banana (fine on its own)
  </Checkbox>
</Checkbox.Group>
```
