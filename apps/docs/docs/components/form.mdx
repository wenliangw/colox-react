# Form

The form layer: a native `<form>` owns the values, the validation policy and the
submit lifecycle, and every field speaks the same family language the controls
already do. Layout is not a second system — fields stack through `Stack` with a
token-keyed `gap`, and anything fancier composes with `Container`/`Grid`/`Stack`
around them.

## Anatomy

A field declares its name, its label, exactly one control and its rules:

<Form
  onSubmit={({ values }) => console.log(values)}
  onInvalid={({ errors }) => console.log(errors)}
>
  <Form.Field name="name">
    <Form.Label>Name</Form.Label>
    <Input placeholder="Ada Lovelace" />
    <Form.Hint>As it should appear on the invoice.</Form.Hint>
    <Form.Validate required />
  </Form.Field>
  <Form.Field name="email">
    <Form.Label>Email</Form.Label>
    <Input placeholder="ada@colox.dev" />
    <Form.Validate required />
    <Form.Validate pattern={/^[^\s@]+@[^\s@]+\.[^\s@]+$/} message="Enter a valid address" />
  </Form.Field>
  <Button type="submit" variant="solid">
    Submit
  </Button>
</Form>

`Form.Field` renders the field container (its `className`, `style` and native
attributes land there), wires `<Form.Label>` to the control, injects the
controlled value and the change channel into its single control child, and
registers the rules its `Form.Validate` leaves declare. Zero or several controls,
several labels, host elements and fragments are hard errors — a field must know
exactly which control it speaks through.

## One payload for every control

Every form leaf publishes the family payload `{ event, value }`, so the field
reads them all with one rule. The controlled word switches by domain: the
boolean leaves (`Checkbox`, `Switch`, a standalone `Radio`) take `checked` —
their `value` prop is a string form token — and every other control takes
`value`.

<Form onInvalid={({ errors }) => console.log(errors)}>
  <Form.Field name="seats">
    <Form.Label>Seats</Form.Label>
    <InputNumber min={1} max={12} defaultValue={2} />
  </Form.Field>
  <Form.Field name="budget">
    <Form.Label>Budget</Form.Label>
    <Slider min={0} max={100} step={10} defaultValue={40} />
  </Form.Field>
  <Form.Field name="fruit">
    <Form.Label>Fruit</Form.Label>
    <Select placeholder="Pick one">
      <Select.Option value="apple" text="Apple" />
      <Select.Option value="banana" text="Banana" />
    </Select>
    <Form.Validate required />
  </Form.Field>
  <Form.Field name="size">
    <Form.Label>Size</Form.Label>
    <Radio.Group>
      <Radio value="sm">Small</Radio>
      <Radio value="lg">Large</Radio>
    </Radio.Group>
    <Form.Validate required />
  </Form.Field>
  <Form.Field name="extras">
    <Form.Label>Extras</Form.Label>
    <Checkbox.Group>
      <Checkbox value="insurance">Insurance</Checkbox>
      <Checkbox value="gift">Gift wrap</Checkbox>
    </Checkbox.Group>
  </Form.Field>
  <Form.Field name="agree">
    <Form.Label>Terms</Form.Label>
    <Switch>I accept the terms</Switch>
    <Form.Validate required />
  </Form.Field>
</Form>

A group control is a `role="group"` / `role="radiogroup"` container rather than a
labelable element, so the field wires it through `aria-labelledby` instead of
`htmlFor` — the label lands on whatever the field actually controls.

## Rules

Each `Form.Validate` leaf declares one rule (or a small ordered set) and owns the
error line it renders. Rules run in declaration order across the field's leaves
and only the first failure shows; the failing leaf renders the message, so the
error can sit wherever the author put the leaf.

<Form>
  <Form.Field name="handle">
    <Form.Label>Handle</Form.Label>
    <Input placeholder="at least 4 characters" />
    <Form.Validate required />
    <Form.Validate minLength={4} />
  </Form.Field>
  <Form.Field name="zip">
    <Form.Label>ZIP</Form.Label>
    <Input placeholder="five digits" />
    <Form.Validate pattern={/^\d{5}$/} message="Enter five digits" />
  </Form.Field>
  <Form.Field name="age">
    <Form.Label>Age</Form.Label>
    <InputNumber />
    <Form.Validate min={18} max={120} />
  </Form.Field>
  <Form.Field name="code">
    <Form.Label>Invite code</Form.Label>
    <Input placeholder="try taken" />
    <Form.Validate
      validate={async (value) => (value === 'taken' ? 'Already taken' : undefined)}
      deps={['handle']}
    />
  </Form.Field>
</Form>

| Rule                    | Type                                                              | Fails when                                                             |
| ----------------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `required`              | `boolean`                                                         | the value is empty — `''`, `null`, `[]` or `false`                     |
| `pattern`               | `RegExp`                                                          | the text does not match                                                |
| `min`/`max`             | `number`                                                          | a number falls outside the bounds                                      |
| `minLength`/`maxLength` | `number`                                                          | text or a selection is shorter/longer                                  |
| `validate`              | `(value, values) => string \| false \| undefined \| Promise<...>` | your rule says so (return the message, or `false` for the generic one) |
| `message`               | `string`                                                          | — (overrides the rule's default message)                               |
| `deps`                  | `string[]`                                                        | — (re-runs this field when a named field changes)                      |

`validate` may be async; v1 shows no pending state while a promise settles, the
error simply appears when it resolves.

## When rules run

`validateOn` is form-wide (`'submit'`, `'blur'`, `'change'` or a mix; default
`['submit', 'blur']`). Submitting always validates everything, and a `deps`
change always re-runs its dependent field regardless of the policy.

## Label placement

`labelPlacement` is `'top'` (default) or `'start'`; the start column's width is a
size token key (`labelWidth`, never a px value). Both are overridable per field.

<Form labelPlacement="start" labelWidth="20" gap="4">
  <Form.Field name="first">
    <Form.Label>First name</Form.Label>
    <Input placeholder="Ada" />
  </Form.Field>
  <Form.Field name="last" labelWidth="28">
    <Form.Label>Last name</Form.Label>
    <Input placeholder="Lovelace" />
  </Form.Field>
  <Form.Field name="note" labelPlacement="top">
    <Form.Label>Back to the top</Form.Label>
    <Input placeholder="Overridden per field" />
  </Form.Field>
</Form>

## Label alignment

Inside the start column, `labelAlign` lines the label text up: `'start'` leads
(default), `'end'` plasters the label against the control, and `'justify'`
spreads the characters across the whole column width — the two-to-four character
label trick that keeps a column of Chinese labels tidy. Declare it on the form,
override it per field; the top placement has no column, so it ignores the axis.

<Form labelPlacement="start" labelWidth="16" labelAlign="end" gap="4">
  <Form.Field name="m-name">
    <Form.Label>姓名</Form.Label>
    <Input placeholder="Ada" />
  </Form.Field>
  <Form.Field name="m-mail" labelAlign="justify">
    <Form.Label>邮箱</Form.Label>
    <Input placeholder="ada@colox.dev" />
  </Form.Field>
  <Form.Field name="m-note" labelAlign="start">
    <Form.Label>备注</Form.Label>
    <Input placeholder="Leads (left)" />
  </Form.Field>
</Form>

## Required mark

A field shows the red `*` while some `Form.Validate required` leaf declares it
required — the mark is derived from the rules, never declared twice.
`requiredMarkPosition` is `'start'` (the mark leads the text) or `'end'`
(antd's trail), set on the form and overridable per field; a label hides its
own mark with `showRequiredMark={false}`. The star travels with the text: the
`labelAlign` axis lines up the whole label — mark and words as one piece — so
it never drifts away from the words. The visual star is decoration — the field
injects `aria-required` into the control as its programmatic twin.

<Form labelPlacement="start" labelWidth="16" labelAlign="end" gap="4">
  <Form.Field name="r-name">
    <Form.Label>姓名</Form.Label>
    <Input placeholder="Ada" />
    <Form.Validate required />
  </Form.Field>
  <Form.Field name="r-mail" requiredMarkPosition="end">
    <Form.Label>邮箱</Form.Label>
    <Input placeholder="ada@colox.dev" />
    <Form.Validate required />
  </Form.Field>
  <Form.Field name="r-address" labelAlign="justify">
    <Form.Label>地址</Form.Label>
    <Input placeholder="Spread label text" />
    <Form.Validate required />
  </Form.Field>
  <Form.Field name="r-note">
    <Form.Label showRequiredMark={false}>备注</Form.Label>
    <Input placeholder="Required but unmarked" />
    <Form.Validate required />
  </Form.Field>
</Form>

## Form-wide controls, focus and per-field policy

`disabled` locks the whole form — every control receives `disabled` and no
field can opt out (the sticky grammar of the groups' disabled inheritance).
While the form is not disabled, an author's own `disabled` on a control keeps
working.

A failed submit moves the viewport to the first invalid field and focuses its
control (a group scrolls only), so a long form lands the eye on the first
error line instead of leaving it off-screen. Turn the landing off form-wide
with `focusOnInvalid={false}`.

A field overrides the form's validation policy with its own `validateOn` —
the classic login mix: the name checked on blur, the password on every
change while `validateOn="change"` stays the form default.

<Form disabled>
  <Form.Field name="f-name">
    <Form.Label>Name</Form.Label>
    <Input />
  </Form.Field>
</Form>

<Form validateOn="change">
  <Form.Field name="p-name" validateOn="blur">
    <Form.Label>Name</Form.Label>
    <Input />
    <Form.Validate required message="Checked on blur" />
  </Form.Field>
  <Form.Field name="p-pass">
    <Form.Label>Password</Form.Label>
    <Input type="password" />
    <Form.Validate required message="Checked on change" />
  </Form.Field>
</Form>

`size` cascades the control width — the same word list every leaf speaks
(`xs | sm | md | lg`) — but it is a state class, not a lock: it lands only on
controls that declared no own `size`, and the control's own word wins.
`colon` appends the `：` to every label, the Chinese admin-form habit,
rendered as a painted piece (the label's text and its queryable name stay the
author's words); a field can opt out per field.

<Form size="sm" colon>
  <Form.Field name="s-org">
    <Form.Label>组织</Form.Label>
    <Input />
    <Form.Validate required />
  </Form.Field>
  <Form.Field name="s-note" colon={false}>
    <Form.Label>备注</Form.Label>
    <Input size="lg" />
  </Form.Field>
</Form>

## The store

`useForm()` creates the store and hands it to `<Form form={store}>` when the
consumer needs it outside the tree; omit it and the form owns one, reachable
inside through `useFormContext()`.

```tsx
const form = useForm({ city: 'Lisbon' });

<Form form={form}>
  <Form.Field name="city">
    <Form.Label>City</Form.Label>
    <Input />
    <Form.Validate required />
  </Form.Field>
</Form>

<Button onClick={() => void form.validate()}>Validate</Button>
<Button onClick={() => form.reset({ city: 'Porto' })}>Reset</Button>
```

`reset(values?)` restores the first frame: fields the given map does not cover
(and, without an argument, every field) go back to their uncontrolled
`defaultValue` / `defaultChecked` — or the `useForm` initial values when they
were declared — and the errors clear. What the controls show and what
`getValues()` reads agree again.

`setValues(partial)` is the edit-form backfill: it merges the given keys over
the current values, runs no validation and reports nothing — a fetched record
loads silently, the rules wait for the user's next edit. A form that holds no
external store declares its initial values on the form itself
(`initialValues`, ignored when a `form` store is passed).

`onValuesChange` fires for every user edit with `{ name, value, values }` —
the changed field, its next value and the post-change snapshot. Programmatic
writes never produce one, so auto-save can watch this channel without saving
back the record it just loaded:

```tsx
<Form
  initialValues={{ name: 'Ada', email: 'ada@colox.dev' }}
  onValuesChange={({ values }) => save(values)}
>
  {/* fields */}
</Form>
```

`useFormWatch(store, name?)` subscribes to values — one field with a name,
the whole map without — and `useFormWatchError(store, name)` to one field's
error. Both are read-only re-render primitives behind dependent fields, live
summaries and auto-save:

```tsx
const form = useForm();
const city = useFormWatch(form, 'city'); // one field
const all = useFormWatch(form); // the whole map, auto-save style
```

## Nested names and unregister

A field name is a dotted path: `name="user.name"` reads and writes the
`user.name` leaf, and every shape the store hands back rebuilds the nested
tree — `getValues()`, `getErrors()`, the rule inputs and the submitted
payload all carry `{ user: { name } }`. The entry points
(`initialValues`, `setValues`, `reset`) accept both spellings — an object
literal or the dotted key (`{ user: { name } }` or `{ 'user.name': name }`).
Object literals are the only shape that expands; arrays and other values are
field values, and never fan out into names.

A field removed from the tree keeps its value like any unmounted field; call
`store.unregister(name)` when it should stop contributing — the registration,
value and error all drop, so a dynamic section can clean up after itself.

## API

### Form props

| Prop                   | Type                                      | Default                   |
| ---------------------- | ----------------------------------------- | ------------------------- |
| `form`                 | `FormStore`                               | the form's own            |
| `initialValues`        | `FormValues`                              | — (form-owned store only) |
| `validateOn`           | `'submit' \| 'blur' \| 'change' \| array` | `['submit','blur']`       |
| `labelPlacement`       | `'top' \| 'start'`                        | `'top'`                   |
| `labelWidth`           | size token key                            | `'24'`                    |
| `labelAlign`           | `'start' \| 'end' \| 'justify'`           | `'start'`                 |
| `requiredMarkPosition` | `'start' \| 'end'`                        | `'start'`                 |
| `size`                 | `'xs' \| 'sm' \| 'md' \| 'lg'`            | controls' own             |
| `colon`                | `boolean`                                 | `false`                   |
| `gap`                  | spacing token key                         | `'4'`                     |
| `disabled`             | `boolean`                                 | `false`                   |
| `focusOnInvalid`       | `boolean`                                 | `true`                    |
| `onSubmit`             | `({ event, values }) => void`             | —                         |
| `onInvalid`            | `({ event, errors }) => void`             | —                         |
| `onValuesChange`       | `({ name, value, values }) => void`       | —                         |

Native `<form>` attributes pass through (`onSubmit`/`onInvalid` are the form
layer's own, and native validation stays off).

### Form.Field / Form.Label / Form.Hint / Form.Validate

| Member          | Props                                                                                                                               |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `Form.Field`    | `name`, `labelPlacement?`, `labelWidth?`, `labelAlign?`, `requiredMarkPosition?`, `validateOn?`, `colon?` + native `div` attributes |
| `Form.Label`    | `showRequiredMark?` + native `label` attributes minus `htmlFor` (the field wires it)                                                |
| `Form.Hint`     | native `div` attributes (yields while the field is invalid)                                                                         |
| `Form.Validate` | the rule props above                                                                                                                |

### Hooks

| Hook                             | Notes                                                                           |
| -------------------------------- | ------------------------------------------------------------------------------- |
| `useForm(initialValues?)`        | creates the store; hand it to `<Form form={store}>` to hold it outside the tree |
| `useFormContext()`               | the form's store and policy, inside the tree                                    |
| `useFormWatch(store, name?)`     | re-renders on the field's value — or the whole map without a name               |
| `useFormWatchError(store, name)` | re-renders on the field's error message                                         |

### FormStore

| Method                               | Notes                                                                             |
| ------------------------------------ | --------------------------------------------------------------------------------- |
| `getValues()` / `getValue(name)`     | the current values                                                                |
| `getErrors()` / `getError(name)`     | the current errors                                                                |
| `isValid()`                          | whether no field carries an error                                                 |
| `setValue(name, value)`              | writes a value (no validation runs)                                               |
| `setValues(values)`                  | edit-form backfill: merges the given keys, silent — no validation, no report      |
| `setError(name, message)`            | a server-side verdict; shows on the field's first error line                      |
| `validate()` / `validateField(name)` | runs the rules and returns the outcome                                            |
| `focusFirstInvalid()`                | the failed-submit landing: moves the viewport to the first invalid field          |
| `reset(values?)`                     | restores the first frame (uncontrolled seeds or initial values) and clears errors |
| `unregister(name)`                   | drops a field: stops validating it, removes its value and error                   |
| `subscribe(listener)`                | re-renders your own readouts                                                      |

## Notes and non-goals

- `Form.FieldArray`, an `InputGroup` and a time picker are not shipped; the
  milestone list in the [roadmap](../roadmap) tracks them.
- Native form attributes still work: `<form>` submission is intercepted only to
  run the rules first, and controls keep their `name` for native `FormData`.
