# Button

Buttons trigger user actions — a single strength ladder, six semantic
families, and one size scale across the whole library.

## When to use

- Use a Button for every visible action: submit, confirm, open, navigate.
- Strong actions sit high on the ladder (`solid`); quieter ones step down
  (`subtle` → `surface` → `outline` → `ghost`) so the page keeps one
  loudest control.
- Semantic color is opt-in — every control defaults to `gray`. Declare a
  `palette` when the action actually means something (`error` for
  destructive, `success` for confirmatory).
- Need an icon-only control? That is an [IconButton](/docs/components/icon-button),
  not a Button.

## API

| Prop    | Type                                                                 | Default   | Description                                                          |
| ------- | -------------------------------------------------------------------- | --------- | -------------------------------------------------------------------- |
| variant | `'solid' \| 'subtle' \| 'surface' \| 'outline' \| 'ghost'`           | `'solid'` | Strength rung — `solid` heaviest, `ghost` lightest.                  |
| palette | `'primary' \| 'gray' \| 'info' \| 'error' \| 'warning' \| 'success'` | `'gray'`  | Semantic family — every control defaults to `gray`; color is opt-in. |
| size    | `'xs' \| 'sm' \| 'md' \| 'lg'`                                       | `'md'`    | Size tier, shared with the other controls.                           |
| shadow  | `boolean`                                                            | `false`   | Elevation via the theme shadow tokens (`md` at rest, `lg` on hover). |

It also accepts all native `<button>` attributes; `type` defaults to `'button'`.
