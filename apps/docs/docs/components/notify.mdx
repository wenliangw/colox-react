# Notify

The **titled card kind** of the message system — the antd-notification
tier. An opaque `bg-default` card holding the semantic mode icon, a
**title** + content and the close button. The heavier sibling of
[Toast](/docs/components/toast) — where Toast is a single-line hint,
Notify is a proper notification. No action slot: a notification
reports and closes; the decision-tier interactions (undo/retry) are a
dialog's job, and custom interactive content rides `Notify.custom`.

Notify shares the message system's container with Toast: one
`<MessageViewport>` per scope holds both kinds' entries side by side,
each in its own slot (Notify defaults to `top-right`, Toast to
`top-center`).

## Container

The same `<MessageViewport>` Toast uses — the container does not care
which kind the entry came from:

```tsx
<MessageViewport />
```

Calls without a `scope` route into `'root'` (the screen-wide fixed
container). A scoped container merges onto your own element with
`asChild` — the element itself becomes the anchor, no wrapper div and
no parent `position: relative` needed:

```tsx
<MessageViewport scope="panel" asChild>
  <div style={{ height: 240, border: '1px dashed gray' }}>...panel content</div>
</MessageViewport>;

Notify.info({ title: 'Panel', content: 'Scoped.' }, { scope: 'panel' });
```

## The imperative API

`Notify.…` is a global namespace — callable from any code position.
The payload carries the card's own shape: `title`, `content`, `mode`,
`palette`, `variant`, `duration`, `key`.

```tsx
Notify.info({
  title: 'Saved',
  content: 'The file is on disk.',
});
```

Mode shortcuts: `Notify.info` / `Notify.success` / `Notify.warning` /
`Notify.error`. `Notify.custom(anyNode)` renders arbitrary content as
the card body. Call options: `scope`, `position` (default `top-right`),
`strategy`, plus the shared chrome/lifecycle axes — `showIcon`
(default `true`), `closeable` (default `true`), `data` and `onClose`
(same semantics as Toast).

## Palette & variant

Like Toast, a notify card's color family is the **palette** (defaulting
to the mode) and its surface is the **variant** (`plain` default,
`subtle` / `solid` / `outline`). The card body (title/content) rides
the variant paint the same way a toast pill does.

```tsx
Notify.error({
  title: 'Upload failed',
  content: 'The file is larger than 10 MB.',
  variant: 'solid',
});
```

## Strategy: stack + fold

Notify defaults to `strategy: 'stack'` — several notifications can
legitimately coexist, each keeping its own timer. To stop a burst from
polluting the viewport, a slot that shows **more than two** notify
cards **folds**: the newest card stays visible, the rest stop rendering
and fold into one **count capsule** reading the tally, with a ✕ that
dismisses the whole slot at once.

While folded, the auto-dismiss countdowns **freeze** — bursting
notifications stop deleting themselves, so nothing is lost behind the
user's back. Closing the visible card **pops the stack in place**: the
popped card leaves **instantly** (no exit animation) and the
next-newest card lands right where it was — the card frame stays put,
the incoming words play the zoom entrance (the same update language as
a single replacement) and the count ticks down; the zoom replays on
**every** reveal. The same holds for a
**new card arriving while the capsule is out**: the slot's frame stays,
the fresh words reveal with the zoom entrance. When the stack is down
to its **last card**, that card resumes its timer and the capsule
becomes a **countdown capsule** reading the remaining seconds — the
slot empties itself at zero; a countdown capsule is a reading, not a
control, so its clear-all ✕ steps back. The exit animation belongs to
the last card alone. Sticky cards (`duration: 0`) never count down, in
or out of a fold; hovering keeps pausing the countdown as usual.

Pass `strategy: 'single'` to replace in place instead — one card per
slot; the slot keeps its identity, the new payload lands **instantly**
and the new words play a **zoom entrance** (exactly like a Toast
replacement), no opacity dip.

## Lifecycle

- **Duration**: auto-dismiss after 3s by default; `duration: 0` is
  sticky. Hovering pauses the countdown.
- **Close**: the corner close button, `Notify.dismiss(id)` /
  `Notify.dismiss()` (all in the scope).
- **Chrome**: `showIcon: false` drops the mode icon, `closeable: false`
  removes the corner ✕ (both default `true`).
- **onClose**: `onClose({ id, data })` fires once when a card's payload
  ends (dismissed, expired, cleared or replaced in place); `data` is the
  opaque passthrough value of that call. `Notify.update` does not fire
  it (the payload continues).
- **Update**: `Notify.update(key, patch)` mutates a live card in place.
  A visible payload change lands instantly: the content node re-mounts
  and plays a **zoom entrance** (a scale + fade on the normal motion
  token) — the update's whole feedback, no opacity dip; an invisible
  patch (duration/key) applies instantly.
- **Exit**: per-item exit animation before the store removes it.

## Positions

The six slots are relative to the **container's own box** — for the
root container that is the screen (top/bottom × left/center/right); for
a scoped container, the box it is pinned inside. Pass `position` to
override the kind default per call.

## Surface

Opaque `bg-default` card (the Popover surface recipe) with the design
language's `md` surface shadow (`--colox-shadow-md` — the
floating-surface tier the popup family shares), radius-lg, no border.
The palette drives the semantic icon color and the `variant` paint
overrides the surface. `role="status"` (polite) announces each card.
