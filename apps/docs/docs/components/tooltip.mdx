# Tooltip

The hint layer on the floating mechanism (the cdk popup). Tooltip renders
**no wrapper element** — it clones its trigger in place, exactly where the
author wrote it, and mounts the panel out of a body portal. The authored DOM
structure stays untouched.

<CodeBlock className="colox-import" language="tsx">{`import { Tooltip } from '@colox/react';
import '@colox/react/style.css';`}</CodeBlock>

## Channels

One name, two channels — and giving both is a compile-time error, never a
priority:

- **Props form**: a single trigger child plus the `content` prop. Falsy content
  (the empty string, `null`, `false`) renders no tooltip — the conditional
  body is free.
- **Composed form**: `<Tooltip.Trigger>` (exactly one; its single child — a
  component or a bare element — becomes the trigger) plus at most one
  `<Tooltip.Content>` for custom DOM. `className`/`style` on the Content part
  are the escape hatch and land on the content box. Composed mode without a
  Content part renders the plain trigger.

Tooltip injects the interaction surfaces (events) plus `aria-describedby`
pointing at the panel id; the trigger element keeps its own props — the
author's `onClick` chains after the tooltip's, `className` concatenates,
existing `aria-describedby` words survive.

```tsx
<Tooltip content="The props form.">
  <Button>Hover me</Button>
</Tooltip>

<Tooltip>
  <Tooltip.Trigger>
    <Button>Custom body</Button>
  </Tooltip.Trigger>
  <Tooltip.Content>
    <Stack direction="column" gap="1">
      <span>Rich DOM</span>
      <span>anything you need</span>
    </Stack>
  </Tooltip.Content>
</Tooltip>
```

## When to use

- Short hints on hover that must never change the DOM around the trigger.
- Custom bodies: the composed channel keeps the trigger and the panel DOM in
  your hands, no wrapper in between.

## Surfaces

`palette` picks the design-language surface family — `gray` (default),
`primary`, `info`, `error`, `warning`, `success`, `white`. Every surface is
**borderless** and **translucent** at the 0.9 alpha tier (the pure-black
translucency rung `--colox-palette-black-900` for the neutral default, the
family solid mixed at 90% for the colors, the white-900 rung with dark ink
for `white`) — the page stays readable through the panel, with **no backdrop
blur** (the frost machinery earned more problems than the look). The arrow is
a **rotated translucent diamond half buried behind the bubble** — no
clip-path, and only the protruding tip corner rounded (radius `xs`; the base
corners stay sharp) — on the same fill; it reads as the bubble surface
sticking out. The depth comes from **one drop-shadow cast on the panel
itself** (the ant-design approach): the outermost container carries the
filter, so the bubble and the visible diamond half silhouette together in a
single pass; the offset follows the arrow direction (the shadow seats on
the gap side in all four orientations), and the color is the design
language's own shadow value (rgba(25, 25, 25, 0.10) — the master alpha
carried by the `--colox-shadow-*` tokens). `size` shifts one
ladder step from the base tier — `sm` / `md` / `lg` — and sizes the arrow too
(`sm` drops the diamond one step). The decorative arrow pins to the
**resolved** placement (after flipping), so it never lies about the side the
panel landed on; it also stays aimed at the trigger when a boundary collision
displaces the panel (flip/shift), clamped so it never leaves the panel.

## Behavior

`visibleOn` picks the trigger channel:

- `"hover"` (default): pointer enter opens after `delay.in` (300ms) with an
  instant focus channel — focusing opens immediately, blur closes. The close
  timer and the open timer always cancel each other, so a fast enter/leave
  never reopens.
- `"click"`: an instant toggle; Escape, outside pointerdown or window blur
  close it.
- `"manual"`: the controlled word — `visible` drives the panel; interactions
  never auto-open or auto-close, and `onVisibleChange` stays silent (it only
  speaks the hover/click transitions).

`closeOnScroll` closes on any scroll while open — an explicit opt-out; the
default follows the trigger through the popup's auto-update stream instead.
`delay` merges partial objects into the defaults (`{ out: 200 }` keeps the
300ms open delay).

## Props

| Prop            | Type                                                                            | Default      |
| --------------- | ------------------------------------------------------------------------------- | ------------ |
| content         | `ReactNode`                                                                     | —            |
| visibleOn       | `'hover' \| 'click' \| 'manual'`                                                | `'hover'`    |
| visible         | `boolean`                                                                       | —            |
| showArrow       | `boolean`                                                                       | `true`       |
| placement       | `Placement`                                                                     | `'top'`      |
| palette         | `'gray' \| 'primary' \| 'info' \| 'error' \| 'warning' \| 'success' \| 'white'` | `'gray'`     |
| delay           | `{ in?, out? }`                                                                 | `{ 300, 0 }` |
| closeOnScroll   | `boolean`                                                                       | `false`      |
| size            | `'sm' \| 'md' \| 'lg'`                                                          | `'md'`       |
| onVisibleChange | `(visible: boolean) => void`                                                    | —            |

## Boundaries

- **The trigger must accept a ref.** A component or host element without ref
  support can't be referenced — no invisible span fallback is injected.
- **Disabled native controls swallow pointer events.** No enter event ever
  reaches a `disabled` button, so no tooltip opens — wrap it in a container
  (an Anchor works) when a disabled trigger still needs an explanation.
- **Animated in and out.** The panel enters with a fade + scale and exits
  with a fade (both driven by the motion tokens); the exit window keeps the
  panel mounted for `--colox-motion-duration-fast` (100ms) so the fade-out
  plays, then unmounts.
- **No `defaultVisible`.** The hover/click channels are presentation-only —
  first-show behavior needs no initial word, and the manual channel is
  controlled.
